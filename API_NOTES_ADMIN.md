# Admin endpoint contract notes

Reviewed against Addepar's official documentation on 2026-09-16. These contracts have offline request/response coverage; no billing, payout, or report schedule writes were performed against a firm.

- **Billing updates replace resources.** `replace_fee`, `replace_fee_schedule`, their bulk variants, and payout replacement methods use PUT. Fees and schedules replace relationships too. Single fee creation sends an array; single billing responses may contain a one-item array, which singular methods unwrap. Bulk methods take complete JSON:API resource dictionaries (`attributes`, optional `relationships`, `id` for replacements); type may be omitted. [Fees](https://developers.addepar.com/docs/fee-rules), [fee schedules](https://developers.addepar.com/docs/fee-schedules).
- **Payout pagination differs.** These APIs use plain `offset`/`limit`, `search`, repeated `recipient_ids`, and `meta.page.total`. Lists retain returned resource shapes unchanged. The payout rule guide inconsistently wraps some list items in another `data` object; the SDK does not silently rewrite that ambiguity. [Recipients](https://developers.addepar.com/docs/payout-recipients), [rules](https://developers.addepar.com/docs/payout-rules).
- **Billable portfolio responses differ by operation.** The existing singular creator still returns a string ID from `{ "id": ... }`. Bulk creation returns the resource array. Bulk schedule reassignment uses `create_billable_portfolio` resources; bulk archive uses `billable_portfolios`. Bulk archive/reassignment are documented as feature-gated and limited to 500 items. [Billable portfolios](https://developers.addepar.com/docs/billing).
- **Schedules:** the path is singular `/report_schedule`, while the guide's resource type is `report_schedules`. Attribute dictionaries preserve optional/new fields and explicit nulls. The guide's filter table conflicts with its example parameter names; callers provide query names verbatim using `params`. [Report schedules](https://developers.addepar.com/docs/report-schedules).
- **Schedule execution is an explicit raw request.** The reference exposes `/report_schedule/{id}/execute` but describes its body only as an object with `data.type` and `data.attributes`. `execute_schedule(id, payload)` therefore requires the caller's full JSON:API document and returns the full response, retaining metadata. No specific execution options are invented. Execution listing returns relationship identifiers, not expanded jobs. [Execute schedule](https://developers.addepar.com/reference/createreportscheduleexecute), [executions](https://developers.addepar.com/reference/getreportscheduleexecutionsrelationships).
- Existing report listing/generation/download routes match the detailed guides. Generation now accepts the documented `brand_id` team ID; label IDs and notification options remain unchanged. [Report generation](https://developers.addepar.com/docs/report-generation), [generated reports](https://developers.addepar.com/docs/generated-reports).
- File uploads now use the shared transport, including authentication, timeout handling, and SDK exceptions. `download_file_to`, `download_archived_file_to`, and `download_zipped_file_to` stream through the client's atomic download helper; existing byte-returning methods remain available.

New entry points: `client.admin.fees`, `fee_schedules`, `payout_recipients`, `payout_rules`, and `report_schedules`. Existing `billable_portfolios` and `reports` methods remain compatible. Other than raw schedule execution, singular operations return resource dictionaries, plural operations return lists, and delete/relationship mutations return `None`.
